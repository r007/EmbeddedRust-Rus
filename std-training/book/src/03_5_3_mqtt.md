### Кодирование и декодирование полезной нагрузки сообщений

Команды светодиода платы состоят из трёх байтов, которые обозначают красный, зелёный и синий.
- `enum ColorData` содержит топик `color_topic(uuid)` и `BoardLed`;
- поле `data()` структуры `EspMqttMessage` можно преобразовать с помощью `try_from()`. Сначала сообщение нужно привести к срезу: `let message_data: &[u8] = &message.data();`


```rust
// команда RGB-светодиода

if let Ok(ColorData::BoardLed(color)) = ColorData::try_from(message_data) { /* установить новый цвет здесь */ }
```

## Публикация и подписка

`EspMqttClient` отвечает не только за публикацию, но и за подписку на топики.

```rust
let subscribe_topic = /* ... */;
client.subscribe(subscribe_topic, QoS::AtLeastOnce)
```

## Дополнительные задания

### Реализуйте MQTT с иерархическими топиками

✅ Выполняйте это, если всё остальное уже готово. Полного решения мы не даём: задача в том, чтобы проверить, как далеко вы продвинетесь самостоятельно.

Посмотрите `common/lib/mqtt-messages`:

✅ Реализуйте ту же процедуру, но с использованием иерархии MQTT. Подписывайтесь на все сообщения «command», комбинируя `cmd_topic_fragment(uuid)` с завершающим шаблоном `#`.

✅ Используйте `enum Command` вместо `enum ColorData`. `enum Command` представляет все возможные команды (здесь — только `BoardLed`).

✅ `RawCommandData` хранит последнюю часть топика сообщения (например, `board_led` в `a-uuid/command/board_led`). Его можно преобразовать в `Command` с помощью `try_from`.

```rust
// команда RGB-светодиода
let raw = RawCommandData {
    path: command,
    data: message.data(),
};
```

Посмотрите `host-client`:

✅ Нужно заменить `color` на `command`. Например, так:

```rust
let command = Command::BoardLed(color)
```

### Другие задания

✅ Используйте [`serde_json`](https://docs.serde.rs/serde_json/), чтобы кодировать и декодировать данные сообщений в JSON.

✅ Отправьте с клиента-хоста несколько сообщений с большой полезной нагрузкой и обработайте их на микроконтроллере. Большие сообщения доставляются по частям вместо `Details::Complete`:

```rust
InitialChunk(chunk_info) => { /* первый фрагмент */},
SubsequentChunk(chunk_data) => { /* все последующие фрагменты */ }
```

💡 Не нужно различать входящие фрагменты по ID сообщения: в любой момент времени в пути может находиться не более одного сообщения.

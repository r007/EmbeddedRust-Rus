# Упражнение: драйвер I²C, простая версия

Мы не будем писать драйвер целиком, только первый шаг: «hello world» написания драйверов, то есть чтение идентификатора устройства датчика. Эта версия называется простой, потому что мы объясняем фрагменты кода, а вам нужно лишь скопировать их в нужное место. Используйте эту версию, если у вас мало опыта работы с Rust, если этот практикум — ваш первый во встраиваемой области или если сложная версия оказалась для вас слишком трудной. Вы можете работать в одном и том же файле с любой из версий.

`i2c-driver/src/icm42670p.rs` — это текст с пропусками, представляющий собой очень простой драйвер IMU-датчика I²C. Задача — дописать файл так, чтобы запуск `main.rs` выводил в лог идентификатор устройства драйвера.

`i2c-driver/src/icm42670p_solution.rs` содержит решение этого упражнения. Чтобы его запустить, нужно поменять импорты в `main.rs` и `lib.rs`. Импорты уже есть: достаточно закомментировать текущие импорты и раскомментировать решения, отмеченные комментариями в строках.

## API драйвера

### Экземпляр датчика

Чтобы работать с периферийным датчиком, сначала нужно получить его экземпляр. Датчик представлен структурой, которая содержит и адрес устройства, и объект, представляющий саму шину I²C. Для этого используются трейты, определённые в крейте [`embedded-hal`](https://docs.rs/embedded-hal/latest/embedded_hal/). Структура публичная, потому что к ней нужен доступ извне крейта, но её поля приватные.

```rust
{{#include ../../advanced/i2c-driver/src/icm42670p_solution.rs:struct}}
```

Добавляем блок `impl`, который будет содержать все методы, доступные для экземпляра датчика. В нём также определяется обработка ошибок. В этом же блоке реализуем метод создания экземпляра. Методы могут быть публичными или приватными. Этот метод должен быть доступен извне, поэтому он помечен как `pub`. Обратите внимание: при такой записи экземпляр датчика становится владельцем шины I²C.

### Адрес устройства

- Адреса устройства доступны в коде:

```rust
{{#include ../../advanced/i2c-driver/src/icm42670p_solution.rs:device_addr}}
```

- У этого устройства I²C два возможных адреса: `0x68` и `0x69`.
Мы указываем устройству, какой адрес использовать, подавая на вывод `AP_AD0` либо `0V`, либо `3.3V`. При `0V` устройство отвечает на адрес `0x68`, при `3.3V` — на `0x69`. Поэтому вывод `AP_AD0` можно считать однобитным входом, который задаёт младший бит адреса устройства.
Подробнее — в [даташите, раздел 9.3](https://invensense.tdk.com/wp-content/uploads/2021/07/DS-000451-ICM-42670-P-v1.0.pdf).

### `read_register()` и `write_register()`

Определим методы _чтения_ и _записи_ на основе методов, которые предоставляет крейт `embedded-hal`. Они служат вспомогательными средствами для более конкретных методов и абстракцией, адаптированной под датчик с 8-битными регистрами. Обратите внимание, что метод `read_register()` основан на методе `write_read()`. Причина — в особенностях протокола I²C: сначала нужно записать по шине команду, которая указывает, из какого регистра мы хотим читать. Вспомогательные методы могут оставаться приватными, так как им не нужен доступ извне крейта.


* чтение измерений.

### 🔎 Общие сведения о регистрах периферии

Регистры могут иметь разный смысл. По сути, это **ячейка, которая может хранить значение**.

В данном случае мы работаем с внешним устройством (поскольку это датчик, даже если он на той же печатной плате). Оно адресуется по I2C, и мы читаем и записываем его адреса регистров. Каждый адрес указывает на уникальную ячейку, которая содержит какую-то информацию. В данном случае нам нужен адрес ячейки, в которой хранится текущая температура, измеренная датчиком.

Карту регистров ICM-42670 можно найти в [разделе 14](https://invensense.tdk.com/wp-content/uploads/2021/07/DS-000451-ICM-42670-P-v1.0.pdf), если вы хотите получить из этого датчика другие интересные данные.

# Низкоуровневый ввод-вывод: как работать с регистрами

Есть [два способа писать прошивку для ESP32-C3](https://esp-rs.github.io/book/overview/index.html):
 - первый — bare-metal, с использованием только `[no_std]` Rust;
 - второй — с использованием `[std]` Rust и C-биндингов к ESP-IDF.

> [`[no_std]` Rust](https://docs.rust-embedded.org/book/intro/no-std.html) — это Rust без стандартной библиотеки, только с [core-библиотекой](https://doc.rust-lang.org/core/). Core — подмножество [стандартной библиотеки](https://doc.rust-lang.org/std/), которое не зависит от наличия операционной системы.

## Как устроены экосистемы?

### `[std]` Rust и ESP-IDF

Этот путь опирается на C-биндинги к ESP-IDF. По этому пути можно использовать стандартную библиотеку Rust, поскольку у нас есть операционная система: ESP-IDF, основанная на [FreeRTOS](https://www.freertos.org/). Возможность пользоваться стандартной библиотекой даёт преимущества: можно использовать любые типы, независимо от того, размещены ли они на стеке или в куче. Можно использовать потоки, `Mutex` и другие примитивы синхронизации.

 ESP-IDF в основном написан на C и открывается в Rust по классической схеме разделения на крейты:
- крейт `sys`, предоставляющий собственно `unsafe`-биндинги ([esp-idf-sys](https://github.com/esp-rs/esp-idf-sys));
- крейт более высокого уровня с безопасными и удобными абстракциями Rust ([esp-idf-svc](https://github.com/esp-rs/esp-idf-svc/)).

Последняя часть головоломки — низкоуровневый доступ к железу, который снова предоставляется в разделённом виде:
- [`esp-idf-hal`](https://github.com/esp-rs/esp-idf-hal) реализует не зависящие от железа трейты [`embedded-hal`](https://github.com/rust-embedded/embedded-hal), такие как аналого-цифровое преобразование, цифровые выводы ввода-вывода или связь по SPI. Как следует из названия, он тоже использует ESP-IDF в качестве основы.

Подробнее — в главе [об экосистеме](https://esp-rs.github.io/book/overview/using-the-standard-library.html) книги _The Rust on ESP Book_.

На сегодняшний день этот путь даёт наибольшие возможности на чипах Espressif, если вы хотите использовать Rust. **Весь материал этого курса основан на этом подходе.**

Как записывать значения в регистры в этой экосистеме, мы рассмотрим в контексте упражнения с прерываниями.

### Bare metal Rust с `[no_std]`

Как следует из названия bare metal, операционная система не используется. Поэтому мы не можем пользоваться возможностями языка, которые на ней основаны. Core-библиотека — это подмножество стандартной библиотеки, которое исключает такие возможности, как типы, размещаемые в куче, и потоки. Код, использующий только core-библиотеку, помечается `#[no_std]`. Код `#[no_std]` всегда может работать в окружении `std`, но обратное неверно.

Регистры и их поля в устройстве описываются в файлах [_System View Description_ (SVD)](http://www.disca.upv.es/aperles/arm_cortex_m3/curset/CMSIS/Documentation/SVD/html/index.html). С помощью [`svd2rust`](https://docs.rs/svd2rust/latest/svd2rust/) по этим файлам генерируются _Peripheral Access Crates_ (PAC). PAC представляет собой тонкую обёртку над различными регистрами с отображением в память, определёнными для конкретной модели используемого микроконтроллера.

Хотя прошивку можно написать и только с PAC, часть кода получилась бы небезопасной или неудобной, так как PAC даёт лишь самый базовый доступ к периферии микроконтроллера. Поэтому есть ещё один слой — _Hardware Abstraction Layer_ (HAL). HAL предоставляет более удобный API для чипа и часто реализует общие трейты, определённые в универсальном [`embedded-hal`](https://github.com/rust-embedded/embedded-hal).

Микроконтроллеры обычно припаяны к какой-нибудь _печатной плате_ (или просто _плате_), которая определяет подключения к каждому выводу. Для конкретной платы может быть написан _Board Support Crate_ (BSC, также известный как _Board Support Package_ или BSP). Он добавляет ещё один слой абстракции и может, например, предоставлять API для различных датчиков и светодиодов на плате, без необходимости знать, к каким выводам микроконтроллера они подключены.

Мы напишем частичный драйвер датчика в таком подходе, так как драйверы должны быть платформонезависимыми.

# HTTP-клиент

Цель этого упражнения — написать небольшой HTTP-клиент, который подключается к веб-сайту.

## Подготовка

✅ Перейдите в папку `intro/http-client`.

✅ Откройте подготовленную заготовку проекта в `intro/http-client`.

✅ Добавьте свои [данные для подключения к сети](02_4_hello_board.md) в `cfg.toml`, как при проверке оборудования.

✅ Откройте документацию этого проекта командой:

```console
cargo doc --open
```

`intro/http-client/examples/http_client.rs` содержит решение. Запустить его можно командой:

```console
cargo run --example http_client
```
## Установка соединения

По умолчанию доступен только незашифрованный HTTP, что довольно сильно ограничивает выбор хостов для подключения. Мы будем использовать `http://neverssl.com/`.

В ESP-IDF HTTP-соединениями клиента управляет `http::client::EspHttpClient` из крейта `esp-idf-svc`. Он реализует трейт `http::client::Client` из `embedded-svc`, который определяет функции для [методов HTTP-запросов](https://en.wikipedia.org/wiki/Hypertext_Transfer_Protocol#Request_methods), таких как `GET` или `POST`. Самое время посмотреть документацию, которую вы открыли командой `cargo doc --open`, для `esp_idf_svc::http::client::EspHttpConnection` и `embedded_svc::http::client::Client`. Изучите доступные методы создания экземпляров.

✅ Создайте новый `EspHttpConnection` с конфигурацией по умолчанию. Подходящий конструктор найдите в документации.

✅ Получите клиент из только что созданного соединения.

Вызов HTTP-методов клиента (например, `get(url)`) возвращает `embedded_svc::http::client::Request`. Его нужно отправить явно: клиент может передавать данные вместе с запросом.

Функция `get` использует [as_ref()](https://doc.rust-lang.org/std/convert/trait.AsRef.html). Это значит, что вместо ограничения одним конкретным типом, например только `String` или только `&str`, функция принимает любой тип, реализующий трейт `AsRef<str>`, то есть любой тип, для которого вызов `.as_ref()` даёт `&str`. Это работает для `String` и `&str`, а также для перечисления `Cow<str>`, которое содержит один из двух предыдущих вариантов.

Успешный ответ содержит [код состояния в диапазоне 2xx](https://en.wikipedia.org/wiki/List_of_HTTP_status_codes), за которым следует исходный HTML сайта.

✅ Проверьте, что соединение прошло успешно.

✅ Возвращайте ошибку, если код состояния не входит в диапазон 2xx.

```rust
match status {
        200..=299 => {
        }
        _ => bail!("Unexpected response code: {}", status),
    }
```
Ошибку статуса можно вернуть с помощью крейта [Anyhow](https://docs.rs/anyhow/latest/anyhow/index.html). Он содержит различные средства для упрощения обработки ошибок на уровне приложения. Крейт предоставляет универсальный `anyhow::Result<T>`, который оборачивает успешный случай (`Ok`) в T и избавляет от необходимости указывать тип Err, при условии что каждая возвращаемая ошибка реализует `std::error::Error`.

## Устранение неполадок

- `missing WiFi name/password`: убедитесь, что `cfg.toml` настроен по образцу `cfg.toml.example`. Частая проблема — имя пакета и имя секции конфигурации не совпадают.

```toml
# Cargo.toml
#...
[package]
name = "http-client"
#...

# cfg.toml
[http-client]
wifi_ssid = "..."
wifi_psk = "..."
```

- `Guru Meditation Error: Core 0 panic'ed (Load access fault). Exception was unhandled.`
    Это может быть вызвано `.unwrap()` в вашем коде. Попробуйте заменить их на оператор `?`.

# Моё решение

Какое решение вы придумали?

Вот моё. Это, вероятно, один из самых простых (хотя, конечно, не самых красивых) способов получить нужную матрицу:

``` rust
{{#include src/main.rs}}
```

И ещё кое-что! Проверьте, что ваше решение работает и в сборке «release»:

``` console
$ cargo embed --release
```

Если хотите отлаживать бинарник «release», понадобится другая команда GDB:

``` console
$ gdb ../../../target/thumbv7em-none-eabihf/release/led-roulette
```

Компилятор Rust изменяет машинные инструкции, которые генерируются в release-сборке (иногда очень сильно), чтобы сделать код быстрее или меньше. К сожалению, после этого GDB с трудом разбирается в происходящем. Поэтому отлаживать release-сборки с GDB бывает непросто.

За размером бинарника всегда стоит следить! Насколько велико ваше решение? Проверить это можно командой `size` для release-бинарника:

Ваши числа могут немного отличаться в зависимости от того, как собран код: это нормально.

Умеете читать этот вывод? Секция `text` содержит инструкции программы. Секция `rodata` содержит данные только для чтения, которые хранятся вместе с инструкциями программы. Секции `data` и `bss` содержат переменные, выделенные статически в RAM (`static`-переменные). Если вы помните характеристики micro:bit, то заметите, что его флеш-память меньше чем вдвое больше размера этого очень простого бинарника. Может ли это быть правдой? Как видно из статистики размеров, основную часть бинарника составляют отладочные секции. Однако они никогда не прошиваются в микроконтроллер: для выполнения программы они не нужны.

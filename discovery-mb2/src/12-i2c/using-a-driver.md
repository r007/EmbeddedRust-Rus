# Использование драйвера

Как мы уже говорили в главе 5, `embedded-hal` предоставляет абстракции, с помощью которых можно писать не зависящий от платформы код для работы с оборудованием. Фактически все методы, которыми мы пользовались для работы с оборудованием в главе [LED-рулетка](../07-led-roulette/index.html) и вплоть до этой главы, были методами трейтов, определённых в `embedded-hal`. Теперь впервые по-настоящему воспользуемся трейтами, которые предоставляет `embedded-hal`.

Писать драйвер для LSM303AGR под каждую платформу, которую поддерживает встраиваемый Rust (и под новые, которые могут появиться), было бы бессмысленно. Чтобы этого избежать, драйвер можно написать так, чтобы он принимал обобщённые типы, реализующие трейты `embedded-hal`, — тогда получается не зависящая от платформы версия драйвера. К счастью, это уже сделано в крейте [`lsm303agr`]. Поэтому чтение реальных значений акселерометра и магнитометра теперь почти работает по принципу «подключи и пользуйся» (плюс немного чтения документации). На странице `crates.io` уже есть всё, что нужно, чтобы читать данные акселерометра, — но для Raspberry Pi. Нам остаётся адаптировать этот пример под наш чип:

[`lsm303agr`]: https://crates.io/crates/lsm303agr

Посмотрите пример кода для Raspberry Pi под Linux на той странице.

Поскольку мы уже знаем, как создать объект, реализующий трейты [`embedded_hal::blocking::i2c`], из [предыдущего раздела](read-a-single-register.md), адаптировать пример просто (`examples/show-accel.rs`):

[`embedded_hal::blocking::i2c`]: https://docs.rs/embedded-hal/0.2.6/embedded_hal/blocking/i2c/index.html

```rust
{{#include examples/show-accel.rs}}
```

Как и в предыдущем фрагменте, попробовать эту программу можно так:
```console
$ cargo embed --example show-accel
```

Кроме того, если немного подвигать micro:bit (физически), вы увидите, как меняются выводимые значения ускорения.
